Paso 0. Clonar y verificar tu entorno con un script real

Prepara tu máquina y ejecuta tu primer motor de admisión de crédito en Python desde tu consola.

1

Comprueba si tienes Git instalado en tu terminal

Paso previo

Abre la terminal de Windows (PowerShell) o abre VS Code (Ctrl + Ñ) y ejecuta:

git --version
¿Qué debes ver en tu terminal?
git version 2.4x.x.windows.1
Si sale error, instala Git desde git-scm.com › y reinicia VS Code.
2

Configura tu identidad en tu terminal (Solo 1 vez en tu máquina)

Global

Para que el banco identifique quién es el autor de cada regla o query, ejecuta tus datos:

git config --global user.name "Tu Nombre y Apellido"
git config --global user.email "tu.correo@bancoppel.com"
3

Clona la biblioteca oficial a tu computadora

Biblioteca central

En tu terminal, ve a tu carpeta de Documentos, clona el repositorio y ábrelo en VS Code:

git clone https://github.com/credito-tdc-bcpl/capacitacion-git-tdc.git
cd capacitacion-git-tdc ; code .
4

Comprueba tu entorno ejecutando ejemplos/reglas_originacion_tdc.py

Prueba en consola

En la terminal integrada de VS Code (Ctrl + Ñ), ejecuta el script de ejemplo para probar las reglas de admisión:

python ejemplos/reglas_originacion_tdc.py

Paso 1. Comenzar el día sincronizando las carpetas del equipo

Descarga en tu consola las últimas queries de cosechas y reglas de incrementos que subieron tus colegas.

Imagina que ayer el equipo de Monitoreo subió la query indicadores-cosechas/seguimiento_cosechas_tdc.sql y el de Portafolio actualizó lineas-credito/reglas_incremento_lineas.py.

Abre la terminal en VS Code (Ctrl + Ñ) y corre:

git pull
Caso A: Ya estás sincronizado
Already up to date.

Significa que ya tienes la versión más reciente de todas las carpetas.

Caso B: Novedades en tu pantalla
Fast-forward
indicadores-cosechas/seguimiento_cosechas_tdc.sql | 18 +++

Los archivos se descargan en segundos a tu explorador de VS Code.

💡

¿Por qué no hay conflictos al hacer pull?

Porque el científico de cosechas trabaja en indicadores-cosechas/ y el estratega de límites en lineas-credito/. Cada uno es dueño de su script y Git los sincroniza sin colisiones.

Paso 2. Editar y compartir una política real (`originacion/reglas_score_buro.py`)

Sigue el ciclo de los 4 pasos en tu terminal tras hacer un ajuste de negocio real en VS Code.

1

Edita el archivo en VS Code y corre `git status` en la terminal

Paso 1 de 4
📋 Caso de negocio:

El Comité de Riesgos acordó subir el score de corte de 650 a 660 puntos.

  1. Abre en tu VS Code el archivo: originacion/reglas_score_buro.py.
  2. Cambia el valor 650 por 660 en la función validar_score_minimo.
  3. Guarda el archivo presionando Ctrl + S.

Ahora en tu terminal de VS Code ejecuta:

git status
Lo que verás en tu consola:
Changes not staged for commit:
modified: originacion/reglas_score_buro.py
2

Prepara el archivo en la caja de envío (`git add .`)

Paso 2 de 4

En tu terminal, ejecuta para meter tu script modificado a la caja de envío (Staging):

git add .

💡 Si vuelves a correr git status, verás que originacion/reglas_score_buro.py ahora aparece en verde ("Changes to be committed").

3

Sella la versión con la justificación del cambio (`git commit -m`)

Paso 3 de 4

En auditoría bancaria, cada commit debe explicar qué política se calibró. Corre en tu consola:

git commit -m "feat(originacion): ajuste de score minimo a 660 segun comite Q4"
Respuesta en tu terminal:
[main 8a1b2c3] feat(originacion): ajuste de score minimo a 660 segun comite Q4
1 file changed, 1 insertion(+), 1 deletion(-)
4

Sube la nueva regla a GitHub (`git push`)

Paso 4 (Final)

Envía la actualización a la organización para que todo el equipo cuente con el nuevo corte de admisión:

git push

Gobernanza con `ejemplos/calculo_roll_rate.sql` y `.gitignore`

En crédito, las fórmulas de transición se comparten; las extracciones con RFC o saldos nunca se suben.

El caso real de Roll Rates y datos confidenciales:

En tu carpeta tienes ejemplos/calculo_roll_rate.sql. Ese archivo SÍ debe estar en GitHub porque contiene la matemática de migración entre buckets (B0, B1, B2) para estimar provisiones IFRS 9.

Sin embargo, cuando corres esa query en Snowflake o Databricks y descargas a tu computadora un archivo como data/cartera_clientes_mora.csv con saldos y RFCs, el archivo .gitignore entra en acción:

Ignorado por .gitignore
  • • *.csv y *.xlsx (Bases de clientes y extracciones).
  • • .env (Contraseñas de conexión a Snowflake/Oracle).
  • • Carpetas de datos locales (data/, raw/).
Controlado por Git
  • • ejemplos/calculo_roll_rate.sql (Query maestro).
  • • ejemplos/reglas_originacion_tdc.py (Lógica de negocio).
  • • README.md (Catálogo y documentación).

Los 5 Comandos Diarios Terminal PowerShell
git pull
Descarga los cambios de tus compañeros en `indicadores/` o `lineas/`.
git status
Muestra en rojo los archivos de política que has modificado.
git add .
Prepara los scripts modificados en la caja de envío (se pintan de verde).
git commit -m "..."
Sella la versión con la justificación del cambio de política.
git push
Sube tu script a la organización central en GitHub.

Solución a los 3 Dolores de Cabeza Más Comunes en Windows

Error 1

"fatal: not a git repository"

Causa: Abriste la terminal fuera de la carpeta del proyecto.

cd capacitacion-git-tdc
Error 2

"Updates were rejected"

Causa: Un compañero subió algo y tú diste push sin haber hecho pull primero.

git pull
git push
Error 3

"Se abrió la pantalla de Vim"

Causa: Escribiste git commit sin poner -m "...".

1. Presiona Esc
2. Escribe :q! y da Enter
