1. Preparación del Entorno

Verifica herramientas, clona el repositorio y ejecuta el primer script de prueba.

1

Verifica si tienes Git instalado

Paso previo

Abre la terminal en VS Code (Ctrl + Ñ) y ejecuta:

git --version
Salida esperada:
git version 2.4x.x.windows.1
Si muestra la versión, pasa al punto 2. Si marca error de comando no reconocido, instálalo a continuación:
⚡

¿No tienes Git? Instálalo con winget:

Gestor nativo de Windows (sin descargas manuales):

winget install --id Git.Git -e --source winget
⚠️ Requisito: Reinicia VS Code tras instalar para actualizar las variables de entorno (PATH).
Sin permisos de admin: Descargar instalador ejecutable (.exe) ›
2

Configura tu identidad (una sola vez)

Global

Identifica la autoría de tus commits con tu nombre y correo institucional:

git config --global user.name "Tu Nombre y Apellido"
git config --global user.email "tu.correo@bancoppel.com"
3

Clona el repositorio desde VS Code

Sin permisos de Admin
💡

En equipos bancarios no requieres GitHub CLI: VS Code clona y se autentica directamente con tu navegador corporativo.

A

Pestaña Welcome

Abre VS Code y en la pantalla inicial haz clic en "Clonar repositorio Git..." (o presiona Ctrl + Shift + P > Git: Clonar).

B

Pega la URL del repositorio

https://github.com/credito-tdc-bcpl/capacitacion-git-tdc.git
C

Autoriza en el navegador

Haz clic en Permitir, inicia sesión con tu usuario corporativo y concede acceso a la organización credito-tdc-bcpl.

D

Selecciona carpeta y abre el proyecto

Elige tu carpeta destino (ej. C:\Users\tu.usuario\Documents\GitHub) y haz clic en Abrir en el aviso de VS Code.

4

Verifica el estado del proyecto

Verificación

Abre la terminal integrada (Ctrl + Ñ) y comprueba la rama:

git status
Salida esperada:
On branch main
Your branch is up to date with 'origin/main'.
nothing to commit, working tree clean

Ejecuta el script de admisión en la terminal (Ctrl + Ñ):

2. Sincronización Diaria (`git pull`)

Descarga las últimas actualizaciones publicadas por tu equipo antes de comenzar tu jornada.

En la terminal (Ctrl + Ñ), ejecuta para sincronizar tu copia local con el repositorio remoto:

git pull
Caso A: Ya estás al día
Already up to date.

Tu copia local tiene la versión más reciente del repositorio.

Caso B: Nuevos cambios
Fast-forward
indicadores-cosechas/seguimiento.sql | 18 +++
lineas-credito/incrementos.py | 22 +++
2 files changed, 40 insertions(+)

Los archivos modificados por tu equipo se descargan automáticamente.

💡

Cero colisiones de código

Al trabajar en submódulos separados por proyecto, Git fusiona las ramas automáticamente sin requerir resolución de conflictos.

3. Flujo de Publicación (4 Pasos)

Ciclo estándar: editar en VS Code, inspeccionar (`status`), preparar (`add`), registrar (`commit`) y publicar (`push`).

1

Edita el archivo y verifica con `git status`

Paso 1 de 4
📋 Caso práctico:

Abre originacion/reglas_score_buro.py, actualiza el corte de 650 a 660 y guarda (Ctrl + S).

En la terminal, comprueba la detección del cambio:

git status
Salida en consola:
Changes not staged for commit:
modified: originacion/reglas_score_buro.py
2

Prepara el archivo (`git add`)

Paso 2 de 4

Coloca el archivo modificado en el área de preparación (staging):

git add originacion/reglas_score_buro.py

💡 Al correr git status, el archivo cambiará a verde (Changes to be committed).

3

Registra el commit (`git commit`)

Paso 3 de 4

Guarda la versión con un mensaje descriptivo para auditoría:

git commit -m "feat(originacion): ajuste de score minimo a 660 segun comite Q4"
Confirmación en consola:
[main 8a1b2c3] feat(originacion): ajuste de score minimo a 660 segun comite Q4
1 file changed, 1 insertion(+), 1 deletion(-)
4

Publica en GitHub (`git push`)

Paso 4 (Final)

Envía los commits locales al repositorio remoto de la organización:

git push origin main

4. Seguridad y Gobernanza (.gitignore)

El código analítico se versiona; los datos con RFC o saldos nunca se suben al repositorio.

Criterio de exclusión en Políticas TDC

Ignorado por .gitignore (Nunca subir)
  • • *.csv y *.xlsx (Extracciones y saldos de clientes).
  • • .env (Credenciales de conexión a bases de datos).
  • • Carpetas locales de datos (data/, raw/).
Versionado en Git (Compartido)
  • • *.sql (Queries maestras y matrices de transición).
  • • *.py (Motores de reglas, scoring y modelos).
  • • README.md (Documentación metodológica).

5. Acordeón Rápido y Errores Comunes

Referencia de comandos cotidianos y soluciones a los errores más frecuentes en Windows.

Los 5 Comandos Diarios PowerShell
git pull
Descarga los cambios publicados por tu equipo.
git status
Muestra el estado de archivos modificados o en staging.
git add <ruta/archivo>
Prepara los archivos modificados para el commit.
git commit -m "..."
Guarda la instantánea con mensaje de auditoría.
git push
Sube tus commits a GitHub.

Solución a Errores Comunes en Windows

Error 0

"git no se reconoce..."

Instala Git con winget y reinicia VS Code por completo.

Error 1

"fatal: not a git repo"

Abre la terminal dentro de la carpeta del proyecto (cd <repo>).

Error 2

"Updates were rejected"

Hubo cambios remotos. Corre git pull --rebase y luego git push.

Error 3

"Se abrió Vim"

Presiona Esc, escribe :q! y pulsa Enter.

Error 4

Error 401 / Auth

Clona desde la pestaña Welcome de VS Code y autoriza en navegador.

Secuencia de terminal (PowerShell):

📖 Referencia de los 7 Pasos Diarios

1 · Navegación Posicionar la terminal en tu repositorio local
cd C:\Users\tu.usuario\Documents\GitHub\originacion-credito

Ubica la terminal dentro de la carpeta del proyecto para que Git reconozca el repositorio.

2 · Hábito Matutino Descargar avances del equipo
git pull origin main

Sincroniza antes de programar para evitar rechazos de push por desfase con tus compañeros.

3 · Entorno Activar entorno virtual (.venv)
.\.venv\Scripts\Activate.ps1

Asegura el uso de librerías homologadas del equipo (Polars, conectores) sin interferir con Windows.

4 · Inspección Auditar archivos modificados
git status

Revisa qué archivos cambiaste y previene agregar por accidente archivos temporales o datos.

5 · Staging Preparar selectivamente tu archivo
git add modelos-scoring/lineas-optimas-pd-m4/analisis_pd_m4.py

Agrega por ruta exacta para garantizar que solo subas código productivo sin datos sensibles.

6 · Snapshot Guardar versión con mensaje de auditoría
git commit -m "feat(originacion): actualiza curva de corte decil 3"

Usa prefijos semánticos (feat, fix, docs) para documentar el motivo del cambio de política.

7 · Publicación Subir commits a GitHub
git push origin main

Transfiere y respalda de forma permanente tus commits en el servidor corporativo de GitHub.

Método Oficial: Clonar desde VS Code

Sin errores 401 y sin requerir permisos de administrador
¿Por qué usar la interfaz de VS Code?

Clonar por terminal en laptops corporativas suele fallar con error 401 Unauthorized por credenciales desactualizadas. VS Code abre tu navegador, almacena la sesión oficial y gestiona los permisos bancarios de forma nativa.

Paso a paso en VS Code:
  1. Pestaña Welcome > clic en "Clonar repositorio Git...".
  2. Pega la URL: https://github.com/credito-tdc-bcpl/originacion-credito.git
  3. Inicia sesión y autoriza a credito-tdc-bcpl.
  4. Selecciona tu carpeta local y haz clic en Abrir.
Secuencia de inicialización (PowerShell):
📥

¿Qué hace "git clone"?

Descarga una copia completa con ramas, archivos e historial, configurando automáticamente el puntero remoto origin.

🔑

Autenticación Segura

Clonar desde VS Code valida tu identidad corporativa vía navegador sin requerir tokens manuales ni permisos de Administrador.

🐍

Aislamiento (.venv)

Crea un sandbox local para que las dependencias de Python (Polars, paquetes) no interfieran con otros proyectos.

⚡

Scripts Disabled en PowerShell

Si PowerShell bloquea scripts al activar el venv, ejecuta: Set-ExecutionPolicy -Scope CurrentUser RemoteSigned.

🛡️ Comandos de Rescate y Auditoría

Soluciones inmediatas para los 5 escenarios cotidianos en consola:

1. Push rechazado (cambios remotos)
git pull --rebase origin main
git push origin main

Descarga cambios del equipo y coloca tus commits encima de forma lineal.

2. Descartar cambios locales
git restore ruta/a/tu/script.py

Revierte el archivo al estado limpio del último commit confirmado.

3. Deshacer "git add" (Staging)
git restore --staged ruta/al/archivo

Saca el archivo del staging area sin borrar ni alterar tu código.

4. Auditar diferencias (diff)
git diff ruta/a/tu/script.py

Muestra adiciones (+) y supresiones (-) línea por línea.

5. Consultar historial reciente (log)
git log --oneline -n 6

Muestra un resumen conciso de los últimos 6 commits con sus hashes y mensajes.
