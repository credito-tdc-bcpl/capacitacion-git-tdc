Módulo 1 • Fundamentos de Arquitectura de Trabajo

Nuestra Organización en GitHub y las Reglas de Convivencia

En el equipo de Políticas de Tarjeta de Crédito (TDC) no usamos Git para complicarnos con ramas infinitas ni resolver choques de código complejos. Usamos GitHub como una Biblioteca Central Segura y Auditable donde cada analista comparte sus scripts de Python y queries de SQL con orden y documentación ejemplar.

1. La Organización

Es la cuenta corporativa del banco donde reside todo el equipo. Garantiza que el código pertenezca a la institución y no se pierda en laptops personales o unidades compartidas desordenadas.

2. El Repositorio Semilla

Nuestro repositorio principal es politicas-credito-tdc. Es como una carpeta maestra con historial de cambios donde se guardan las políticas de originación y límites.

3. La Regla de Convivencia

Cero conflictos: Cada analista trabaja exclusivamente en los scripts de su indicador o proyecto. Si necesitas algo del script de un compañero, copias la función o le avisas, pero nunca sobreescribes directamente su archivo.

Módulo 2 • Tus Primeros Comandos en la Terminal de Windows

Descargar la Primera Vez vs Actualizar Todos los Días

El 90% de la confusión de los principiantes se resuelve entendiendo esta regla de oro: git clone se hace una sola vez en la vida por máquina. git pull se hace todas las mañanas antes de empezar a trabajar.

Paso Inicial (Solo 1 vez) git clone <url>

Descargar toda la biblioteca

Crea una carpeta en tu computadora con todo el historial de scripts de crédito del banco. Si ya tienes la carpeta en tu equipo, NO vuelvas a clonar, porque te dará el error: fatal: destination path already exists.

git clone https://github.com/.../politicas-tdc.git
Tu Hábito Diario Obligatorio git pull

Traer novedades de tus compañeros

Imagina que ayer tu colega subió el nuevo cálculo de cosechas indicador_icv.sql. Con git pull tu computadora descarga esos cambios en 2 segundos para que siempre trabajes con la versión más reciente.

Módulo 3 • El Flujo Central de Trabajo

El Ciclo para Compartir tu Código: La Analogía de la Paquetería 📦

Cuando terminas tu script de crédito y quieres que el equipo lo vea, sigues exactamente 4 pasos. Piensa en esto como enviar un paquete por mensajería bancaria:

1
git status

Ver qué cambió

Miras tu escritorio. Git te muestra en rojo los archivos que creaste o modificaste y que aún no has preparado.

2
git add .

Meter a la caja

Tomas los archivos modificados y los colocas dentro de la caja de envío (Staging). Ahora aparecen en verde.

3
git commit -m "..."

Sellar y etiquetar

Cierras la caja con cinta adhesiva y le pegas una etiqueta clara explicando qué cambio hiciste (mínimo 10 caracteres).

4
git push

Enviar el camión

Envías el paquete por la red hasta la Organización de GitHub. ¡Listo! Ya lo pueden ver tus compañeros y tu líder técnico.

🌿
¿Sabías que VS Code te muestra esto en su interfaz gráfica?

En la barra lateral izquierda de VS Code, el ícono con 3 bolitas conectadas (Control de Código Fuente) muestra tus archivos con la letra U (Untracked) o M (Modified). El botón + equivale a git add y el botón de palomita a git commit.

Módulo 4 • Gobernanza Bancaria y Protección de Datos

Documentación Profesional y Seguridad Estricta (.gitignore)

En un banco o institución de crédito, el código no es un borrador casual: es una política financiera auditable. Además, subir una base con clientes o contraseñas a GitHub constituye una falta grave regulatoria.

🛠️ Solución a los 3 Problemas Más Comunes en Windows

Problema 1:

"fatal: not a git repository"

Causa: Abriste la terminal en tu carpeta personal (C:\Users\tu.nombre) y no dentro de la carpeta del proyecto.

# Solución: entra a la carpeta
cd politicas-credito-tdc
Problema 2:

"Updates were rejected (hacer pull antes)"

Causa: Un colega subió un cambio a GitHub y tú intentaste hacer git push sin haberte sincronizado primero.

# Solución: baja cambios y reintenta
git pull
git push
Problema 3:

"Se abrió una pantalla extraña (Editor Vim)"

Causa: Escribiste git commit sin poner -m "mensaje" y Windows te abrió el editor de texto Vim de consola.

# Solución de escape:
1. Presiona la tecla Esc
2. Escribe :q! y presiona Enter
3. Corre: git commit -m "..."

Guía Especial: Cómo subir cambios usando una Cuenta Secundaria de GitHub

Configuración limpia y segura en Windows sin alterar tu cuenta personal/global.

Paso 1: Identidad Local (Solo este repo)

Configura el autor para que los commits queden a nombre de tu cuenta secundaria (sin la bandera --global):

git config user.name "TuUsuarioSecundario"
git config user.email "correo@secundario.com"
Paso 2: Generar Token en GitHub (PAT)

En tu cuenta secundaria de GitHub: Settings > Developer Settings > Personal Access Tokens (Classic). Marca permisos repo y copia el token generado (ghp_xxxx).

Paso 3: Subir con Token en la URL

Para que Windows no use las credenciales guardadas de tu otra cuenta, asigna el token directo en el remote:

git remote set-url origin https://TOKEN@github.com/usuario/repo.git
git push -u origin main
