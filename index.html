Conexión Yellowbrick y Métricas Compartidas

Cada monorepo incluye un paquete interno shared/ para no reescribir conexiones ni métricas de mora.

Reglas Oficiales del Stack Python:
  • Conexión centralizada: Usa from shared.db import query_to_polars en lugar de quemar conexiones con credenciales.
  • Métricas oficiales: En Cartera y Monitoreo, usa from shared.metricas import calcular_mora_90_plus.
  • Entorno virtual obligatorio: Crea siempre tu .venv e instala con pip install -r requirements.txt.
modelo_script_equipo_tdc.py 
"""
================================================================================
INSTITUCIÓN FINANCIERA - DIRECCIÓN DE RIESGO DE CRÉDITO TDC
================================================================================
ARCHIVO:            calculo_score_y_mora_cartera.py
DOMINIO:            [Originación / Cartera / Monitoreo]
AUTOR:              [Tu Nombre Completo / Analista TDC]
CORREO:             [tu.nombre@bancoppel.com]
FECHA CREACIÓN:     2026-10-28
TICKET / JIRA:      POL-TDC-2026-Q4

OBJETIVO DE NEGOCIO:
    Extracción optimizada desde Yellowbrick y cálculo de banderas de morosidad
    utilizando Polars y el módulo corporativo shared.
================================================================================
"""

import sys
import polars as pl
from shared.db import query_to_polars

# Parámetros de Política Institucional
SCORE_CORTE_MINIMO: int = 655
DIAS_MORA_CRITICA: int = 90


def extraer_datos_segmento() -> pl.DataFrame:
    """Extrae cuentas activas desde Yellowbrick utilizando query_to_polars."""
    query = """
        SELECT 
            numero_cuenta_hash,
            fecha_apertura,
            bc_score,
            dias_atraso,
            saldo_capital,
            limite_credito
        FROM dwh_riesgo.cartera_activa_tdc
        WHERE fecha_corte = CURRENT_DATE()
        LIMIT 10000;
    """
    return query_to_polars(query)


def calcular_indicadores_riesgo(df: pl.DataFrame) -> pl.DataFrame:
    """Calcula banderas de riesgo y porcentaje de utilización de línea."""
    return df.with_columns([
        (pl.col("bc_score") >= SCORE_CORTE_MINIMO).alias("flag_score_aprobado"),
        (pl.col("dias_atraso") >= DIAS_MORA_CRITICA).alias("flag_mora_90_plus"),
        (pl.col("saldo_capital") / pl.col("limite_credito") * 100).round(2).alias("pct_utilizacion")
    ])


if __name__ == "__main__":
    print("=== Corriendo análisis con Polars y Yellowbrick ===")
    df_raw = extraer_datos_segmento()
    df_resultado = calcular_indicadores_riesgo(df_raw)
    print(df_resultado.head(5))
Reglas Oficiales del Stack SQL (Yellowbrick):
  • Estructura con CTEs (WITH): Modulariza pasos con expresiones de tabla comunes.
  • Filtrar siempre por partición: Incluye fecha_corte = CURRENT_DATE() para no saturar memoria.
  • Prohibido SELECT *: Nombra explícitamente las columnas necesarias para auditoría.
consulta_yellowbrick_oficial.sql 
/*
================================================================================
INSTITUCIÓN FINANCIERA - DIRECCIÓN DE RIESGO DE CRÉDITO TDC
================================================================================
ARCHIVO:            extraccion_cuentas_candidatas_cli.sql
MOTOR:              Yellowbrick SQL (PostgreSQL Dialect)
AUTOR:              [Tu Nombre Completo / Analista TDC]
PERIODICIDAD:       Mensual (Día 11 de cada mes)
================================================================================
*/

WITH base_cuentas AS (
    SELECT 
        numero_cuenta_hash,
        fecha_apertura,
        limite_credito,
        saldo_actual,
        bc_score,
        dias_atraso
    FROM dwh_riesgo.cartera_activa_tdc
    WHERE fecha_corte = CURRENT_DATE()
      AND dias_atraso = 0
      AND bc_score >= 655
),

metricas_utilizacion AS (
    SELECT 
        numero_cuenta_hash,
        ROUND((saldo_actual / NULLIF(limite_credito, 0)) * 100, 2) AS pct_utilizacion
    FROM base_cuentas
)

SELECT 
    bc.numero_cuenta_hash,
    bc.bc_score,
    bc.limite_credito,
    mu.pct_utilizacion,
    ROUND(bc.limite_credito * 1.30, -2) AS nuevo_limite_propuesto
FROM base_cuentas bc
INNER JOIN metricas_utilizacion mu
    ON bc.numero_cuenta_hash = mu.numero_cuenta_hash
WHERE mu.pct_utilizacion BETWEEN 50.0 AND 85.0
ORDER BY nuevo_limite_propuesto DESC;

Los 4 Mandamientos del Trabajo en Monorepos TDC

Reglas esenciales para garantizar la armonía y continuidad operativa entre 8 científicos de datos:

1.

Aislamiento por Submódulo = Cero Conflictos

Cada científico de datos trabaja dentro de su carpeta asignada. Si Luis Enrique edita pd-m4-lineas-optimas/ y Andrea trabaja en segmentacion-riesgo/, Git fusiona ambos trabajos de forma automática sin pedir resolución de conflictos.

2.

El Hábito Sagrado del "git pull" Matutino

En un monorepo activo, tus compañeros suben avances a diario. Todas las mañanas al abrir tu Visual Studio Code, el primer comando obligatorio antes de escribir una sola línea siempre es git pull.

3.

Gobernanza del Paquete "shared/"

Los archivos shared/db.py y shared/metricas.py son de uso común para todo el equipo. No modifiques su código sin previa coordinación y autorización de la Gerencia de Políticas TDC.

4.

Blindaje de PII y Credenciales (.env)

Toda consulta a Yellowbrick se hace en código. Jamás subas extractos .csv, .xlsx ni contraseñas en .env. El .gitignore del repositorio ya los bloquea, pero es responsabilidad de cada analista cuidar los datos de los clientes.
