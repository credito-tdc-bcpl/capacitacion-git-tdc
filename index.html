Comprueba si tienes Git instalado en tu máquina

Paso previo

Abre la terminal de Windows (PowerShell) o abre VS Code y presiona Ctrl + Ñ. Ejecuta:

3

Primera Vez

En tu terminal, ve a tu carpeta de Documentos y descarga la biblioteca de políticas:

git clone https://github.com/jaguzmanbcpl/capacitacion-git-tdc.git
Luego entra a la carpeta y ábrela en Visual Studio Code:

Tu primer acto cada mañana: `git pull`

Obligatorio Diario

Antes de comenzar a escribir o modificar un script de crédito, siempre debes asegurarte de tener lo que tus compañeros subieron el día anterior. Solo toma 2 segundos.

git pull
Caso A: Nadie ha subido nada nuevo

Significa que ya tienes la versión más reciente en tu laptop.

Caso B: Algún colega subió scripts
Fast-forward
indicadores/cosechas.sql | 45 ++++
2 files changed, 107 insertions(+)

Se descargaron automáticamente a tu carpeta.

🤝 Regla de Convivencia del Equipo

Cada analista trabaja en su archivo dentro de su carpeta asignada (originacion/, lineas-credito/, indicadores-cosechas/). Al no tocar el mismo archivo simultáneamente, nunca tendrás conflictos de código al hacer `git pull`.

El Ciclo de 4 Pasos: La Analogía de la Caja 📦

Cuando terminas o modificas un script y quieres subirlo a GitHub, sigue este orden exacto en tu terminal:

status ➔ add ➔ commit ➔ push
1 git status — Ver qué modificaste
Paso 1

Muestra en rojo los archivos que creaste o editaste y que aún no están listos para enviarse:

git status
Untracked files:
lineas-credito/mi_script_nuevo.py
2 git add . — Meter a la caja de envío
Paso 2

Prepara todos los archivos modificados. El punto (.) significa "agrega todo lo que haya cambiado":

git add .

💡 Si vuelves a correr git status, verás que tus archivos ahora están en verde ("Changes to be committed").

3 git commit -m "..." — Sellar la caja y etiquetarla
Paso 3

Guarda la versión con una nota explicativa. Recuerda incluir siempre -m "tu mensaje" para no caer en el editor de consola:

git commit -m "feat(lineas): matriz de aumento de limites cosecha octubre"

📋 Regla del área: Los mensajes deben ser descriptivos (qué política o cálculo se modificó). Evita mensajes como "cambios" o "prueba".

4 git push — Enviar la caja a GitHub
Paso 4 (Final)

Sube tus cambios por internet al repositorio de la organización. Tus compañeros y líderes ahora podrán verlos:

git push
🚨 Regla de Oro de Seguridad Bancaria y Regulatoria

En este repositorio SOLO SE COMPARTE CÓDIGO (`.py`, `.sql`, `.md`). Por regulación bancaria y privacidad de datos, está estrictamente prohibido subir bases con información de clientes o contraseñas a GitHub.

🚫 NUNCA SUBIR (Bloqueado por .gitignore)
  • •
    Bases de datos: Archivos .csv, .xlsx, .parquet con RFC, saldos o buró.
  • •
    Contraseñas: Archivos .env o credenciales de conexión a bases de datos.
  • •
    Carpetas pesadas: Entornos virtuales (venv/, __pycache__/).
✅ SÍ SE SUBE (El trabajo del equipo)
  • •
    Scripts en Python: Archivos .py con reglas de admisión, scorecuts y matrices.
  • •
    Queries en SQL: Archivos .sql para extracción de cosechas o roll rates.
  • •
    Documentación: Archivos README.md explicando cómo usar cada script.

🛠️ Solución a los 3 Dolores de Cabeza Más Comunes en Windows

Error 1:
"fatal: not a git repository"

Causa: Abriste la terminal fuera de la carpeta del proyecto.

cd capacitacion-git-tdc
Error 2:
"Updates were rejected (hacer pull)"

Causa: Un compañero subió algo a GitHub y tú intentaste dar push sin sincronizarte.

git pull
git push
Error 3:
"Se abrió una pantalla extraña (Editor Vim)"

Causa: Escribiste git commit sin poner -m "...".

2. Escribe :q! y da Enter
