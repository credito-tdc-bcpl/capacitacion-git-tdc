Paso 0. Preparar tu entorno

Verifica que tu computadora tenga Git listo antes de clonar el repositorio semilla.

1

Comprueba si tienes Git instalado

Verificación previa

Abre la terminal en Visual Studio Code (Ctrl + Ñ) o en PowerShell y corre:

git --version
Salida esperada
git version 2.4x.x.windows.1
Si arroja un error en rojo, instala Git en 2 minutos desde git-scm.com › y reinicia VS Code.
2

Configura tu nombre y correo (Solo 1 vez en la vida)

Global

Esto asocia tus cambios a tu identidad profesional para la trazabilidad y auditoría de las políticas de crédito:

git config --global user.name "Tu Nombre y Apellido"
git config --global user.email "tu.correo@banco.com"
3

Descarga el repositorio a tu máquina (`git clone`)

Biblioteca central

Posiciónate en tu carpeta de trabajo y clona el proyecto semilla de Políticas TDC:

git clone https://github.com/jaguzmanbcpl/capacitacion-git-tdc.git

Luego entra a la carpeta y ábrela en Visual Studio Code:

cd capacitacion-git-tdc ; code .

Paso 1. Comenzar el día con `git pull`

Tu primer acto cada mañana antes de redactar código. Sincroniza las novedades de tus colegas en 2 segundos.

Abre la terminal en VS Code (Ctrl + Ñ) y escribe:

git pull
Escenario A: Ya estás al día
Already up to date.

Significa que ningún compañero ha subido cambios nuevos desde tu última sincronización. Puedes comenzar a trabajar con tranquilidad.

Fast-forward

Git bajó los últimos scripts creados por el equipo directamente a tus carpetas locales.

Regla de Oro: Cada analista en su carpeta

Al trabajar en originacion/, lineas-credito/ o indicadores-cosechas/ sin modificar los archivos de otros compañeros al mismo tiempo, nunca tendrás conflictos de Git al hacer pull.

El Ciclo de 4 Pasos. La Analogía de la Caja 📦

Cuando terminas o modificas un script y quieres subirlo a GitHub, sigue este orden en tu terminal:

1

git status

— Ver qué cambió
Paso 1 de 4

Muestra en rojo los archivos que has creado o modificado y que aún están fuera de la caja:

git status
2

git add .

— Meter a la caja de envío
Paso 2 de 4

Prepara todos los archivos modificados. El punto (.) significa "incluye todo":

git add .
3

git commit -m "..."

— Sellar y etiquetar
Paso 3 de 4

Guarda la versión con una nota explicativa. Recuerda siempre incluir -m "mensaje" para no caer en el editor Vim:

git commit -m "feat(lineas): actualiza matriz de aumento de limites"
4

git push

— Enviar a la Organización
Paso 4 (Final)

Sube tus cambios por internet a GitHub para que queden disponibles para el equipo y tu líder:

git push

Gobernanza de Datos. El archivo `.gitignore`

En crédito, el código se comparte; los datos de los clientes y las contraseñas se protegen.

Prohibido Subir
  • —
    Bases de clientes: Archivos .csv, .xlsx o .parquet con RFC, saldos o buró.
  • —
    Credenciales bancarias: Archivos .env o contraseñas de bases de datos.
  • —
    Entornos virtuales: Carpetas locales venv/ o cachés.
Permitido Subir
  • —
    Scripts en Python: Archivos .py con reglas de admisión, scorecuts y matrices.
  • —
    Queries en SQL: Archivos .sql de cálculo de cosechas o roll rates.
  • —
    Documentación: Archivos README.md explicando cómo funciona tu modelo.

Los 5 Comandos Esenciales Terminal PowerShell
git pull
Descarga novedades de tus compañeros (hacer todas las mañanas).
git status
Muestra qué archivos has creado o modificado.
git add .
Prepara todos tus cambios en la caja de envío.
git commit -m "..."
Sella la versión con una nota explicativa de política.
git push
Envía tus cambios a la biblioteca central en GitHub.

Solución a los 3 Dolores de Cabeza Más Comunes en Windows

Error 1

"fatal: not a git repository"

Causa: Abriste la terminal fuera de la carpeta del proyecto.

cd capacitacion-git-tdc
Error 2

"Updates were rejected"

Causa: Un compañero subió algo y tú diste push sin haber hecho pull primero.

git pull
git push
Error 3

"Se abrió la pantalla de Vim"

Causa: Escribiste git commit sin poner -m "...".

1. Presiona Esc
2. Escribe :q! y da Enter
